## Storage Pools

**Storage Pools** in Windows Server are a feature of **Storage Spaces** that let you group multiple physical drives together into a single pool of storage. From that pool, we can then create virtual **disks (storage spaces)** with specific configurations like resiliency, performance, or capacity.

### How Storage Pools Work
| **Component**             | **Description**                                                                                                                  |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **Physical Drives**       | Multiple HDDs or SSDs added together to form a storage pool.                                                                     |
| **Storage Pool**          | A logical container that combines multiple physical drives into a single storage resource.                                       |
| **Virtual Disk – Simple** | Stripes data across drives for **higher performance**, but provides **no fault tolerance**.                                      |
| **Virtual Disk – Mirror** | Duplicates data across multiple drives for **fault tolerance**. If one drive fails, the data remains available.                  |
| **Virtual Disk – Parity** | Stores **parity information** across drives to provide **redundancy** while using storage space more efficiently than mirroring. |

### Create Vitual Disk Of Mirror

| **Feature**            | **Mirror Virtual Disk**                                                                                             |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **Definition**         | A virtual disk that stores **duplicate copies of data** across multiple physical drives to provide fault tolerance. |
| **How It Works**       | Every piece of data written to the virtual disk is copied to another disk (mirrored).                               |
| **Minimum Drives**     | **2** physical drives (for a two-way mirror).                                                                       |
| **Fault Tolerance**    | Can continue operating if **one drive fails** (two-way mirror).                                                     |
| **Performance**        | **Good read performance** and **good write performance** because data is duplicated instead of calculating parity.  |
| **Storage Efficiency** | Lower efficiency because only about **50% of the total storage** is usable in a two-way mirror.                     |
| **Advantages**         | Provides high data protection, fast recovery, and good performance.                                                 |
| **Disadvantages**      | Requires more storage capacity since data is stored twice.                                                          |
| **Best Use Cases**     | File servers, important business data, virtual machines, and workloads requiring high availability.                 |
